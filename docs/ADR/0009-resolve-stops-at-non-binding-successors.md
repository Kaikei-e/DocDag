# 0009: `resolve` は binding でない後継の手前で止まり、その後継を保留として報告する

## コンテキスト

`docdag resolve <id>` は、`supersedes` の辺を後継の方向にたどり、その葉を「いまこの参照の代わりに
効力を持つ記録」として返す。エージェントや周辺ツールは、古い ADR への参照を現行の記録に読み替えるために
これを使う。

0005 は、`period:` を宣言した kind について、この非対称を解消した。後継がまだ採択されていないか、
有効期間に入っていなければ、前身が効力を持ち続ける。`resolve` はそこで止まり、`--binding` と同じ集合を
答える。

しかし `period:` を宣言しないコーパス（`adr` preset を使う大半の利用者）では、`ResolveAt` が
`Resolve` にそのまま委ねられ、status を見ずに辺をたどっていた。Alt では次の状態が実際に起きた。

- 000970〜000973（`status: proposed`）が、000974〜000977（同じく `proposed`）に置き換えられた。
- `docdag query --binding` は、どちらの組も返さない（採択されていないため）。
- `docdag resolve 000970` は `000974` を返す。

同じコーパスについて、`--binding` は「どれも効力を持たない」と言い、`resolve` は「未採択の 000974 が
現行だ」と言う。`resolve` の答えを信じて参照を読み替えたエージェントは、採択されていない提案を
現行の決定として扱うことになる。

## 決定

**`resolve` は、前身に代わって効力を持ちうる後継だけをたどる。**

- 後継をたどる条件は、その status が kind の語彙で正規化して `accepted` であること、かつ `period:` を
  宣言した kind では as-of 時点で有効期間内にあること。`period:` の有無にかかわらず同じ条件を使う。
- 条件を満たさない後継（`proposed` / `rejected` / `withdrawn` など）の辺はたどらず、前身を答えにする。
- たどらなかった後継は捨てずに報告する。テキスト出力では stderr に
  `note: 000974 supersedes 000970 but is proposed; not yet binding` を出す。JSON 出力では `pending`
  配列に入れる。
- 辺だけをたどる `graph.Resolve(g, id, t)` は、生の系譜が必要な呼び出し元のために残す。CLI の
  `resolve` は status を考慮する経路を通す。

## 根拠（調査結果・出典）

- **実測（Alt）** — 変更前は `resolve 000970` が `000974` を返した。変更後は `000970` を返し、
  000974 が proposed であることを stderr に注記する。
- **0005 のコンテキスト** — この非対称は 0005 がすでに「`--binding` と `resolve` の非対称」として
  指摘しており、`period:` を持つ kind についてだけ解消していた。本 ADR は、同じ原理を `period:` を
  持たないコーパスに広げる。

## 検討した代替案

- **従来どおり辺をたどり、葉が binding でなければ警告だけ出す** — 答えそのものが未採択の記録のままなので、
  出力を機械的に使う呼び出し元（エージェント、スクリプト）は警告を見落とす。答えを正しくする方を採った。
- **`--only-binding` フラグで opt-in にする** — 既定の答えが `--binding` と矛盾したまま残る。
  0007 と同じく、誤った答えを既定で返さないことを優先した。
- **binding でない後継を無言で無視する** — 「置き換えが準備中である」という情報が失われる。
  `pending` として残せば、呼び出し元は必要なら後継も参照できる。

## 影響とトレードオフ

- **得るもの** — `resolve` と `query --binding` が同じコーパスについて矛盾しなくなる。
- **判定の二重化** — `resolve` の条件（accepted かつ期間内）は `--binding` と同じ意味を狙っているが、
  `binding:` 射影を読む実装を共有してはいない。`spec` preset のように `binding:` を独自に定義した
  コーパスでは、両者がずれうる。共通の述語へまとめるのは今後の課題とする。
- **振る舞いの変更** — `docdag new` で後継を `proposed` として作った直後に `resolve` すると、以前は
  新しい記録を返していたが、今は前身を返す。後継を採択（`accepted`）した時点で答えが後継に移る。
  既存のテスト 1 件の期待値をこの意味に合わせて改めた。
- **status の意味づけへの依存** — `resolve` の答えが status の書き方に依存するようになる。status の
  書き忘れは、以前は答えに影響しなかったが、今は答えを変える。
